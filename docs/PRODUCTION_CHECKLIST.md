# قائمة ما قبل الإنتاج

راجعها قبل توجيه عملاء حقيقيين للنظام.

---

## 🔴 حاجز — لا تشغّل بدونها

- [ ] **`LLM_PROVIDER` ليس `mock`.** الوهمي للاختبار فقط ولا يفهم اللغة.
- [ ] **`INTERNAL_API_KEY` عشوائي وطويل** — `openssl rand -hex 32`. من يملكه يقرأ كل بيانات العملاء.
- [ ] **`WHATSAPP_APP_SECRET` مضبوط و`WHATSAPP_REQUIRE_SIGNATURE=true`.**
      بدونه يستطيع أي أحد انتحال رسائل عملاء. (المخطط يرفض الإقلاع في هذه الحالة.)
- [ ] **توكن واتساب دائم** من System User، لا توكن الـ٢٤ ساعة.
- [ ] **HTTPS فقط** على المسار العام.
- [ ] **`npm run migrate` نُفّذ** على قاعدة الإنتاج.
- [ ] **`.env` غير مرفوع** إلى Git — تحقق: `git check-ignore .env`.
- [ ] **لا بيانات تجريبية في الإنتاج.** استخدم `--kb-only`، وتحقق:
      ```sql
      SELECT slug FROM tenants;                                  -- لا 'demo-store'
      SELECT count(*) FROM orders WHERE order_number LIKE 'SA-1%'; -- 0
      ```

## 🟠 قبل أول عميل حقيقي

- [ ] **قاعدة المعرفة مليئة ببيانات متجرك الفعلية** — شحن، استرجاع، استبدال، دفع، ضمان، تواصل.
      كل سؤال غير مغطّى = تصعيد لموظف. ابدأ بأكثر ٢٠ سؤالاً تكراراً.
- [ ] **حقل `keywords` معبّأ بالصيغ المحكية** التي يكتبها عملاؤك، لا الصيغة الرسمية.
      هذا أهم عامل منفرد في جودة الردود بالعربي.
- [ ] **جداول `orders` و`products` متصلة ببيانات حقيقية** (مزامنة أو API).
      بدونها كل سؤال عن طلب ينتهي بتصعيد.
- [ ] **`HANDOFF_NOTIFY_CHANNEL` مضبوط ومختبر.** التصعيد الذي لا يصل موظفاً هو عميل ضائع.
      اختبره فعلياً: `POST /internal/v1/handoffs` وتأكد أن الإشعار وصل.
- [ ] **يوجد من يتابع التصعيدات** في ساعات العمل، ومسار واضح للردّ.
- [ ] **`tenants.settings` معبّأ** — `brandName`، `supportHours`، `supportPhone`.
- [ ] **مراجعة بشرية لعيّنة ردود** بنموذج حقيقي (`npm run smoke` مع مفتاح فعلي).
      اقرأها كعميل: هل تبدو طبيعية؟ قصيرة؟ باللهجة الصحيحة؟

## 🟡 التشغيل

- [ ] **نسخ احتياطي يومي** لقاعدة البيانات، **مع اختبار استرجاع فعلي مرة واحدة على الأقل.**
- [ ] **مراقبة `/readyz`** من نظام مراقبة خارجي.
- [ ] **تنبيه على تصاعد الأخطاء**:
      ```sql
      SELECT count(*) FROM agent_logs
      WHERE status='error' AND created_at > now() - interval '15 minutes';
      ```
- [ ] **تنبيه على تكدّس التصعيدات**:
      ```sql
      SELECT count(*) FROM human_handoffs
      WHERE status IN ('pending','notified') AND created_at < now() - interval '30 minutes';
      ```
- [ ] **متابعة التكلفة** — `SELECT * FROM v_agent_daily_stats ORDER BY day DESC;`
      وضع سقف تنبيه شهري.
- [ ] **تنظيف دوري** لجداول `agent_logs` و`webhook_events` و`rate_limit_counters`
      (مهمة يومية تحذف ما هو أقدم من ٩٠ / ٣٠ / ١ يوم).
- [ ] **`RATE_LIMIT_*` مضبوطة** لحجم مرورك — تحمي من إساءة الاستخدام وتفجّر التكلفة.
- [ ] **حدّ إنفاق على مفتاح الـLLM** من لوحة المزوّد.

## 🔵 الأمان والامتثال

- [ ] **PostgreSQL غير مكشوف للإنترنت.** في `docker-compose.yml` المنفذ مربوط على `127.0.0.1` فقط.
- [ ] **`INTERNAL_API_KEY` لا يُمرَّر عبر الإنترنت المفتوح.** ضع n8n والخدمة على شبكة خاصة،
      أو ضع بوابة أمام `/internal/v1/*`.
- [ ] **تدوير المفاتيح** موثّق (مفتاح داخلي، توكن واتساب، مفتاح LLM).
- [ ] **سياسة الاحتفاظ بالبيانات** محدّدة — المحادثات تحتوي بيانات شخصية.
- [ ] **العملاء يعرفون أنهم يكلّمون نظاماً آلياً** (متطلب في كثير من الأنظمة).
      البرومبت لا يدّعي أنه إنسان، لكن الإفصاح الصريح قرارك.
- [ ] **مراجعة الوصول للسجلات** — `agent_logs` و`messages` تحتوي نصوص محادثات كاملة.

## 🟢 التوسّع (بيع النظام لعدة شركات)

- [ ] **مستأجر منفصل لكل شركة** — صف في `tenants` + صف في `channel_accounts`.
      لا نشر ولا تغيير كود. مختبر في `tests/integration/tools.test.ts`.
- [ ] **قاعدة معرفة منفصلة لكل مستأجر** — العزل مختبر آلياً.
- [ ] **`tenants.settings.disabledTools`** لتعطيل أدوات لعميل معيّن بدون نشر.
- [ ] **`tenants.settings.alwaysEscalateIntents`** لتصعيد نوايا بعينها حسب سياسة كل عميل.
- [ ] **تقارير الاستهلاك لكل مستأجر** — `v_agent_daily_stats` تعطيك التوكنز والتكلفة يومياً.
- [ ] **تشغيل عدة نسخ خلف موازن حِمل** — الخدمة عديمة الحالة؛ الحالة كلها في Postgres.
      منع التكرار وحد المعدل يعملان عبر النسخ لأنهما في قاعدة البيانات.

## بعد الإطلاق: أول أسبوع

راجع يومياً:

```sql
-- ما الذي دفع الوكيل للتصعيد؟ (كل صف = فجوة في قاعدة المعرفة)
SELECT reason_code, count(*) FROM human_handoffs
WHERE created_at > now() - interval '1 day' GROUP BY 1 ORDER BY 2 DESC;

-- ردود حجبها فاحص الاستناد (تعني أن النموذج حاول اختلاق معلومة)
SELECT detail->'violations' AS violations, count(*) FROM agent_logs
WHERE step='guardrail.blocked' AND created_at > now() - interval '1 day'
GROUP BY 1 ORDER BY 2 DESC;

-- الأسئلة التي لم تجد إجابة في قاعدة المعرفة
SELECT detail->'input'->>'query' AS q FROM agent_logs
WHERE step='tool.search_knowledge_base' AND detail->'summary'->>'count' = '0'
  AND created_at > now() - interval '1 day' LIMIT 50;
```

الاستعلام الأخير هو قائمة عملك: كل سؤال فيه يجب أن يصبح مدخلة في قاعدة المعرفة.
نسبة التصعيد تنخفض بشكل حاد في أول أسبوعين إن تابعت هذه القائمة.
