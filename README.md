# صفحة الكورس المجاني

نظام Landing Page كامل لتوزيع كورس مجاني مقابل الإيميل فقط:

```
الزائر يدخل إيميله → يضغط "استلم الكورس مجانًا" → ينفتح له /course فورًا
```

بدون OTP، بدون تسجيل دخول، بدون موافقة يدوية. الإيميل يُحفظ تلقائيًا (بدون تكرار)، وصفحة الكورس محمية خلف كوكي موقّع — محد يقدر يفتحها بدون ما يسجّل إيميله فعلًا.

## الستاك (مجاني ١٠٠٪، صفر خدمات مدفوعة)

- **Next.js** (App Router + TypeScript) — عرض وسيرفر في مشروع واحد
- **SQLite** (`better-sqlite3`) — قاعدة بيانات ملف واحد على القرص، صفر إعداد خارجي، صفر تكلفة
- **Tailwind CSS v4** — تصميم Mobile-first و RTL كامل بالعربي
- لا حساب Auth، لا خدمة بريد مدفوعة، لا تخزين سحابي — كل شي يشتغل من الصندوق

> لماذا SQLite بدل Google Sheets/Supabase؟ لأنه فعليًا أبسط وأسرع وبدون أي حساب خارجي أو حدود استخدام مجانية تنتهي — ملف واحد على القرص. الوحيد المطلوب منك هو استضافة عندها قرص دائم (راجع قسم "النشر" تحت — فيه خيارات مجانية).

## بنية المشروع (وين تعدّل كل شي)

| الملف | وش فيه |
|---|---|
| **`src/config/course.ts`** | 🎯 **الملف الوحيد اللي غالبًا تحتاج تعدّله** — اسم البراند، اسم الكورس، الوصف، رابط الصورة، رسالة الترحيب، وقائمة الدروس (عنوان + رابط لكل درس) |
| `src/app/page.tsx` | الصفحة الرئيسية (طلب الإيميل) |
| `src/app/course/page.tsx` | صفحة الكورس بعد استلام الهدية (محمية بكوكي) |
| `src/app/success/page.tsx` | صفحة نجاح احتياطية (رابط يدوي للكورس) |
| `src/app/api/subscribe/route.ts` | نقطة الاستقبال: تتحقق من الإيميل، تحفظه، تحط الكوكي |
| `src/lib/db.ts` | قاعدة البيانات (SQLite) — إنشاء الجدول، منع التكرار |
| `src/lib/token.ts` | توقيع/تحقق كوكي الجلسة (HMAC) |

## كيف تشغّله محليًا

```bash
npm install
cp .env.example .env
```

افتح `.env` وحط قيمة عشوائية طويلة لـ `APP_SECRET` (تقدر تولّدها بـ `openssl rand -hex 32`).

```bash
npm run dev
```

افتح `http://localhost:3000`. جرّب الرحلة كاملة: أدخل إيميل → تنتقل تلقائيًا لـ `/course` → تشوف قائمة الدروس.

## البيانات اللي تحتاج تغيّرها (كلها في ملف واحد)

افتح `src/config/course.ts` وعدّل:

```ts
export const courseConfig = {
  brandName: "اسمك أو براندك",        // ← اسمك/براندك
  courseName: "اسم الكورس المجاني هنا", // ← اسم الكورس
  courseDescription: "...",             // ← وصف مختصر للكورس
  heroImageUrl: "",                     // ← رابط صورة/كرت الكورس (اتركه فاضي لإخفائها)
  welcomeMessage: "...",                // ← رسالة الترحيب في صفحة الكورس
  lessons: [
    { title: "الدرس الأول: ...", description: "...", url: "https://..." },
    // أضف/احذف دروس براحتك — كل درس عنوان + وصف اختياري + رابط
  ],
};
```

رابط كل درس ممكن يكون فيديو يوتيوب غير مدرج، رابط Google Drive، Notion، أو أي منصة تستضيف فيها المحتوى — الصفحة تفتحه بزر "شاهد الدرس" في تبويب جديد.

بعد أي تعديل على هذا الملف، احفظ وأعد تشغيل `npm run dev` محليًا، أو ادفع (`git push`) لو المشروع منشور — Next.js يبني الصفحات من جديد تلقائيًا.

## كيف تشوف الإيميلات المسجلة

```bash
npm run subscribers
```

يطبع جدول فيه كل إيميل، تاريخ التسجيل، هل فتح الكورس، وكم مرة. قاعدة البيانات ملف عادي على `data/app.db` — تقدر أيضًا تفتحه بأي برنامج SQLite (مثل DB Browser for SQLite) لو تبي تصفح البيانات بصريًا أو تصدّرها CSV.

**الإيميلات ما تظهر أبدًا لأي زائر أو في أي صفحة عامة** — الوصول الوحيد لها هو من جهازك عبر هذا الأمر أو مباشرة من ملف قاعدة البيانات.

### لوحة إدارة بسيطة من المتصفح (بديل عن `npm run subscribers`)

إذا تبي تشوف قائمة الإيميلات من جوالك أو أي متصفح بدون طرفية (Terminal)، فعّل صفحة `/admin`:

1. حط قيمة قوية في متغير البيئة `ADMIN_PASSWORD` (محليًا وفي الاستضافة).
2. افتح `https://رابطك/admin` وسجّل دخول بنفس كلمة المرور.

الصفحة محمية بكلمة المرور، غير مفهرسة في محركات البحث، وما تعرض أي شي للزوار العاديين. بدون تعيين `ADMIN_PASSWORD`، الصفحة تكون معطّلة تلقائيًا.

## آلية الحماية

1. بعد إرسال الإيميل، السيرفر يحط كوكي موقّع (HttpOnly + Secure + SameSite=Lax) يثبت إن هذا المتصفح فعلاً سجّل بإيميل صحيح.
2. صفحة `/course` تتحقق من الكوكي على السيرفر قبل ما تعرض أي شي — بدون كوكي صالح، يرجعك لـ `/` تلقائيًا.
3. الإيميل الواحد ما يتكرر أبدًا في قاعدة البيانات (قيد UNIQUE)، وإعادة إدخاله يعيد تسجيل الدخول فقط بدون إنشاء صف جديد.
4. الكوكي موقّع بـ HMAC (`APP_SECRET`) — محد يقدر يزوّره أو يدخل صفحة الكورس بدون ما يمر فعلًا عبر نموذج الإيميل.

## مزامنة الإيميلات مع Google Sheets (اختياري)

قاعدة البيانات الأساسية والموثوقة تبقى SQLite (`data/app.db`) — هذا القسم يضيف **نسخة مطابقة** لكل إيميل جديد في Google Sheet داخل Google Drive تبعك، عشان تقدر تفتحه وتشوف الإيميلات من جوالك بدون ما تدخل السيرفر.

### الإعداد (خمس دقائق، مجاني بالكامل)

1. أنشئ Google Sheet جديد فاضي في حسابك (sheets.new).
2. من القائمة: **Extensions ← Apps Script**.
3. امسح الكود الافتراضي، وانسخ محتوى [`google-apps-script/subscribers-sync.gs`](google-apps-script/subscribers-sync.gs) من هذا المستودع والصقه كامل.
4. احفظ (Ctrl+S)، ثم **Deploy ← New deployment**.
5. اختر النوع **Web app**، واضبط:
   - Execute as: **Me**
   - Who has access: **Anyone**
6. اضغط **Deploy**، وانسخ الرابط اللي يبدأ بـ `https://script.google.com/macros/s/.../exec`.
7. حط هذا الرابط في متغير البيئة `GOOGLE_SHEETS_WEBHOOK_URL` (محليًا في `.env`، وفي الاستضافة أيضًا).

بعدها كل إيميل جديد (غير مكرر) بينضاف تلقائيًا كصف في شيت اسمه "Subscribers". لو تركت المتغير فاضي، الميزة تكون معطّلة تلقائيًا والتطبيق يشتغل عادي بدونها.

## النشر على الإنترنت (مجانًا)

هذا التطبيق يخزّن قاعدة بياناته كملف SQLite على القرص، فيحتاج استضافة عندها **قرص دائم (persistent disk)** — وليس دوال Serverless عادية (مثل Vercel Functions) اللي تمسح ملفاتها بعد كل طلب.

أسهل خيارات مجانية ومناسبة:

### Railway (الأسهل)
1. أنشئ مشروع جديد → اربطه بهذا المستودع والفرع.
2. أضف Volume صغير (١ جيجا كافي) وثبّته على مسار `/data`.
3. عيّن متغيرات البيئة (تحت "Environment Variables"):
   ```
   APP_SECRET=<قيمة عشوائية طويلة>
   DB_PATH=/data/app.db
   ```
4. عدّل `src/config/course.ts` بمعلوماتك الحقيقية قبل الدفع (`git push`).
5. أوامر البناء والتشغيل الافتراضية تكفي: `npm install && npm run build` ثم `npm run start`.

### Render
نفس الفكرة: "Web Service" (وليس Static Site) + Disk مرفق على `/data` + نفس متغيرات البيئة.

### إذا تصر على Vercel
لازم تستبدل SQLite بقاعدة بيانات مُستضافة مجانًا (مثل Postgres على Vercel/Supabase/Neon، أو Google Sheets عبر Apps Script) لأن نظام الملفات فيه مؤقت. هذا يحتاج تعديل بسيط في `src/lib/db.ts` فقط — بقية الكود (التحقق، التوقيع، الصفحات) ما يتغيّر.

## خطوات متبقية منك

1. **عدّل** `src/config/course.ts` بمعلوماتك الحقيقية: اسم الكورس، الوصف، رابط الصورة، ورابط كل درس.
2. **ولّد** `APP_SECRET` حقيقي وحطه في بيئة الإنتاج (لا تستخدم القيمة التجريبية من جهازك).
3. **اختر استضافة** فيها قرص دائم (Railway أو Render أعلاه) واربطها بهذا المستودع (الفرع الافتراضي).
4. **اختبر الرابط النهائي** بعد النشر بنفس الخطوات: إيميل صحيح → إيميل خاطئ → نفس الإيميل مرتين → فتح كل درس من الجوال.
5. بعدها الرابط جاهز للنشر في TikTok / Instagram / X.

## n8n-mcp

هذا المستودع مهيّأ أيضًا لاستخدام [n8n-mcp](https://github.com/czlonkowski/n8n-mcp)، وهو خادم Model Context Protocol يعطي مساعدات الذكاء الاصطناعي وصول منظّم لعقد n8n وتوثيقها وأدوات التحقق من صحة سير العمل.

الخادم مسجّل في [`.mcp.json`](.mcp.json) ويشتغل عبر `npx n8n-mcp`، فما يحتاج خطوة تثبيت منفصلة — Claude Code (أو أي عميل يدعم MCP) بيجيبه ويشغّله تلقائيًا.

افتراضيًا يشتغل بوضع **docs-only**: البحث عن العقد، البحث في التوثيق، والتحقق من صحة سير العمل تشتغل من الصندوق بدون أي حاجة لتشغيل نسخة n8n فعلية.

لتفعيل الأدوات الإضافية اللي تنشئ/تنشر سير عمل على نسخة n8n حقيقية، `.mcp.json` يقرأ `N8N_API_URL` و`N8N_API_KEY` من بيئتك (`${N8N_API_URL}` / `${N8N_API_KEY}`) بدل ما تكون مكتوبة مباشرة، لأن هذا المستودع عام وهذي بيانات حساسة.

1. أنشئ ملف `.env` (مو نفس `.env` الخاص بصفحة الكورس — استخدم متغيرات منفصلة أو صدّرها في جلستك) فيه:
   ```
   N8N_API_URL=https://your-n8n-instance.com
   N8N_API_KEY=your-api-key
   ```
2. حمّلها في الجلسة قبل تشغيل عميل الـ MCP، مثلًا:
   ```bash
   set -a && source .env && set +a
   ```
3. أعد تشغيل عميل الـ MCP (أو شغّل `/mcp` داخل Claude Code) عشان يلتقط التغيير.

**لا ترفع `.env` أبدًا** — موجود في `.gitignore` لهذا السبب بالضبط.
