# صفحة الهدية المجانية

نظام Landing Page كامل لتوزيع هدية مجانية مقابل الإيميل فقط:

```
الزائر يدخل إيميله → SUBMIT → ينفتح له /gift فورًا
```

بدون OTP، بدون تسجيل دخول، بدون موافقة يدوية. الإيميل يُحفظ تلقائيًا (بدون تكرار)، وصفحة الهدية محمية خلف كوكي موقّع — محد يقدر يفتحها بدون ما يسجّل إيميله فعلًا.

## الستاك

- **Next.js** (App Router + TypeScript) — عرض وسيرفر في مشروع واحد
- **SQLite** (`better-sqlite3`) — قاعدة بيانات ملف واحد على القرص، صفر إعداد خارجي
- **Tailwind CSS v4** — تصميم Mobile-first و RTL كامل بالعربي
- لا حساب Auth، لا خدمة بريد مدفوعة — كل شي يشتغل من الصندوق

## بنية المشروع (وين تعدّل كل شي)

| الملف | وش فيه |
|---|---|
| `src/app/page.tsx` | الصفحة الرئيسية (طلب الإيميل) |
| `src/app/gift/page.tsx` | صفحة الهدية بعد التسجيل — تعرض الملف وزر تحميل |
| `src/app/admin/page.tsx` | لوحة إدارة محمية بكلمة مرور لعرض المسجلين |
| `src/app/api/subscribe/route.ts` | نقطة الاستقبال: تتحقق من الإيميل، تحفظه، تحط الكوكي |
| `src/app/api/gift-file/route.ts` | تسليم ملف الهدية عبر رابط موقّع قصير الصلاحية |
| `src/lib/db.ts` | قاعدة البيانات (SQLite) — إنشاء الجدول، منع التكرار |
| `src/lib/token.ts` | توقيع/تحقق كوكي الجلسة والرابط الموقّع (HMAC) |
| `src/lib/gift.ts` | إعداد مصدر الهدية (ملف محلي أو رابط خارجي) |
| `src/lib/googleSheets.ts` | مزامنة اختيارية للإيميلات مع Google Sheet |

## كيف تشغّله محليًا

```bash
npm install
cp .env.example .env
```

افتح `.env` وحط قيمة عشوائية طويلة لـ `APP_SECRET` (تقدر تولّدها بـ `openssl rand -hex 32`).

```bash
npm run dev
```

افتح `http://localhost:3000`. جرّب الرحلة كاملة: أدخل إيميل → تنتقل تلقائيًا لـ `/gift` → تشوف الملف.

## كيف تضيف رابط/ملف الهدية الحقيقي

**الحالة الشائعة — ملف (PDF أو HTML):**
انسخ ملفك الحقيقي إلى `private-gift/gift.html` (بنفس الاسم)، أو خلّه بأي اسم وعدّل `.env`:

```
GIFT_FILE_PATH=./private-gift/الخريطة.pdf
GIFT_FILE_NAME=خريطتي.pdf
```

الملف **ما يظهر أبدًا** كرابط مباشر في أي صفحة — يتسلّم فقط عبر `/api/gift-file` برابط موقّع (HMAC) صالح لـ ١٠ دقائق ومربوط بإيميل الشخص نفسه، ويتجدد تلقائيًا كل مرة يفتح فيها `/gift`.

**إذا كانت الهدية رابط خارجي** (ملف Google Drive، خريطة أونلاين، إلخ) بدل ملف تستضيفه بنفسك:

```
GIFT_EXTERNAL_URL=https://example.com/your-gift-link
```

لما تحط هذا المتغير، صفحة `/gift` تعرض زر يفتح الرابط مباشرة بدل عرض ملف محلي.

## كيف تشوف الإيميلات المسجلة

```bash
npm run subscribers
```

يطبع جدول فيه كل إيميل، تاريخ التسجيل، هل فتح الهدية، وكم مرة. قاعدة البيانات ملف عادي على `data/app.db` — تقدر أيضًا تفتحه بأي برنامج SQLite (مثل DB Browser for SQLite) لو تبي تصفح البيانات بصريًا أو تصدّرها CSV.

**الإيميلات ما تظهر أبدًا لأي زائر أو في أي صفحة عامة** — الوصول الوحيد لها هو من جهازك عبر هذا الأمر، أو من لوحة `/admin`، أو مباشرة من ملف قاعدة البيانات.

### لوحة إدارة بسيطة من المتصفح (بديل عن `npm run subscribers`)

إذا تبي تشوف قائمة الإيميلات من جوالك أو أي متصفح بدون طرفية (Terminal)، فعّل صفحة `/admin`:

1. حط قيمة قوية في متغير البيئة `ADMIN_PASSWORD` (محليًا وفي الاستضافة).
2. افتح `https://رابطك/admin` وسجّل دخول بنفس كلمة المرور.

الصفحة محمية بكلمة المرور، غير مفهرسة في محركات البحث، وما تعرض أي شي للزوار العاديين. بدون تعيين `ADMIN_PASSWORD`، الصفحة تكون معطّلة تلقائيًا.

## مزامنة الإيميلات مع Google Sheets (اختياري)

قاعدة البيانات الأساسية والموثوقة تبقى SQLite (`data/app.db`) — هذا القسم يضيف **نسخة مطابقة** لكل إيميل جديد في Google Sheet داخل Google Drive تبعك، عشان تقدر تفتحه وتشوف الإيميلات من جوالك بدون ما تدخل السيرفر.

### الإعداد (خمس دقائق، مجاني بالكامل)

1. أنشئ Google Sheet جديد فاضي في حسابك (sheets.new).
2. من القائمة: **Extensions ← Apps Script**.
3. امسح الكود الافتراضي، وانسخ محتوى [`google-apps-script/subscribers-sync.gs`](google-apps-script/subscribers-sync.gs) من هذا المستودع والصقه كامل.
4. احفظ (Ctrl+S)، ثم **Deploy ← New deployment**.
5. اختر النوع **Web app**، واضبط:
   - Execute as: **Me**
   - Who has access: **Anyone**
6. اضغط **Deploy**، وانسخ الرابط اللي يبدأ بـ `https://script.google.com/macros/s/.../exec`.
7. حط هذا الرابط في متغير البيئة `GOOGLE_SHEETS_WEBHOOK_URL` (محليًا في `.env`، وفي الاستضافة أيضًا).

بعدها كل إيميل جديد (غير مكرر) بينضاف تلقائيًا كصف في شيت اسمه "Subscribers". لو تركت المتغير فاضي، الميزة تكون معطّلة تلقائيًا والتطبيق يشتغل عادي بدونها. المزامنة لا تحجب ولا تفشّل عملية التسجيل أبدًا حتى لو الرابط غير متاح — SQLite يبقى دايمًا مصدر الحقيقة.

## آلية الحماية

1. بعد إرسال الإيميل، السيرفر يحط كوكي موقّع (HttpOnly + Secure + SameSite=Lax) يثبت إن هذا المتصفح فعلاً سجّل بإيميل صحيح.
2. صفحة `/gift` تتحقق من الكوكي على السيرفر قبل ما تعرض أي شي — بدون كوكي صالح، يرجعك لـ `/` تلقائيًا.
3. رابط الملف نفسه يحمل توقيع HMAC + وقت انتهاء (10 دقائق)، مربوط بإيميلك تحديدًا — نسخ الرابط ومشاركته مع شخص ثاني ما ينفع، وبعد ١٠ دقائق يصير غير صالح تلقائيًا.
4. الإيميل الواحد ما يتكرر أبدًا في قاعدة البيانات (قيد UNIQUE)، وإعادة إدخاله يعيد تسجيل الدخول فقط بدون إنشاء صف جديد.
5. لوحة `/admin` محمية بكوكي موقّع منفصل، غير مفهرسة في محركات البحث، ومعطّلة تلقائيًا بدون `ADMIN_PASSWORD`.

## النشر على الإنترنت

هذا التطبيق يخزّن قاعدة بياناته كملف SQLite على القرص، فيحتاج استضافة عندها **قرص دائم (persistent disk)** — وليس دوال Serverless عادية (مثل Vercel Functions) اللي تمسح ملفاتها بعد كل طلب.

أسهل خيارات مناسبة:

### Railway (الأسهل)
1. أنشئ مشروع جديد → اربطه بهذا المستودع والفرع.
2. أضف Volume صغير (١ جيجا كافي) وثبّته على مسار `/data`.
3. عيّن متغيرات البيئة (تحت "Variables"):
   ```
   APP_SECRET=<قيمة عشوائية طويلة>
   DB_PATH=/data/app.db
   ```
4. ارفع ملف الهدية الحقيقي ضمن الكود قبل النشر (`private-gift/gift.html`) أو استخدم `GIFT_EXTERNAL_URL`.
5. أوامر البناء والتشغيل الافتراضية تكفي: `npm install && npm run build` ثم `npm run start`.

### Render
نفس الفكرة: "Web Service" (وليس Static Site) + Disk مرفق على `/data` + نفس متغيرات البيئة.

### إذا تصر على Vercel
لازم تستبدل SQLite بقاعدة بيانات مُستضافة (مثل Postgres على Vercel/Supabase/Neon) لأن نظام الملفات فيه مؤقت. هذا يحتاج تعديل بسيط في `src/lib/db.ts` فقط — بقية الكود (التحقق، التوقيع، الصفحات) ما يتغيّر.

## المتغيرات البيئية

| المتغير | إلزامي | الوصف |
|---|---|---|
| `APP_SECRET` | ✅ نعم | مفتاح توقيع الكوكي ورابط الملف الموقّع. ولّده بـ `openssl rand -hex 32` ولا تشاركه أبدًا. |
| `DB_PATH` | لا | مسار ملف قاعدة البيانات. افتراضي: `./data/app.db` |
| `GIFT_FILE_PATH` | لا | مسار ملف الهدية على القرص. افتراضي: `./private-gift/gift.html` |
| `GIFT_FILE_NAME` | لا | اسم الملف اللي يظهر للمستخدم عند التحميل |
| `GIFT_EXTERNAL_URL` | لا | إذا معبّى، الهدية تصير رابط خارجي بدل ملف محلي |
| `ADMIN_PASSWORD` | لا | يفعّل لوحة `/admin` لعرض المسجلين من المتصفح |
| `GOOGLE_SHEETS_WEBHOOK_URL` | لا | يفعّل مزامنة الإيميلات الجدد مع Google Sheet |

## خطوات متبقية منك

1. **استبدل** `private-gift/gift.html` بملفك الحقيقي (أو عيّن `GIFT_EXTERNAL_URL`).
2. **ولّد** `APP_SECRET` حقيقي وحطه في بيئة الإنتاج (لا تستخدم القيمة التجريبية من جهازك).
3. **اختر استضافة** فيها قرص دائم (Railway أو Render أعلاه) واربطها بهذا المستودع.
4. **اختبر الرابط النهائي** بعد النشر: إيميل صحيح → إيميل خاطئ → نفس الإيميل مرتين → تحميل الهدية من الجوال.
5. بعدها الرابط جاهز للنشر في TikTok / Instagram / X.

## n8n-mcp

هذا المستودع مهيّأ أيضًا لاستخدام [n8n-mcp](https://github.com/czlonkowski/n8n-mcp)، وهو خادم Model Context Protocol يعطي مساعدات الذكاء الاصطناعي وصول منظّم لعقد n8n وتوثيقها وأدوات التحقق من صحة سير العمل.

الخادم مسجّل في [`.mcp.json`](.mcp.json) ويشتغل عبر `npx n8n-mcp`، فما يحتاج خطوة تثبيت منفصلة — Claude Code (أو أي عميل يدعم MCP) بيجيبه ويشغّله تلقائيًا.

افتراضيًا يشتغل بوضع **docs-only**: البحث عن العقد، البحث في التوثيق، والتحقق من صحة سير العمل تشتغل من الصندوق بدون أي حاجة لتشغيل نسخة n8n فعلية.

لتفعيل الأدوات الإضافية اللي تنشئ/تنشر سير عمل على نسخة n8n حقيقية، `.mcp.json` يقرأ `N8N_API_URL` و`N8N_API_KEY` من بيئتك (`${N8N_API_URL}` / `${N8N_API_KEY}`) بدل ما تكون مكتوبة مباشرة، لأن هذا المستودع عام وهذي بيانات حساسة.

1. أنشئ ملف `.env` منفصل فيه:
   ```
   N8N_API_URL=https://your-n8n-instance.com
   N8N_API_KEY=your-api-key
   ```
2. حمّلها في الجلسة قبل تشغيل عميل الـ MCP، مثلًا:
   ```bash
   set -a && source .env && set +a
   ```
3. أعد تشغيل عميل الـ MCP (أو شغّل `/mcp` داخل Claude Code) عشان يلتقط التغيير.

**لا ترفع `.env` أبدًا** — موجود في `.gitignore` لهذا السبب بالضبط.
