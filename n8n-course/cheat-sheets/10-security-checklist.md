# 🔐 Security Checklist

## الأسرار
```
[ ] لا مفتاح واحد مكتوب داخل عقدة
[ ] كل الأسرار في Credentials أو Environment Variables
[ ] مفاتيح منفصلة: تطوير / إنتاج
[ ] أقل صلاحية ممكنة لكل مفتاح
[ ] تدوير دوري
[ ] .env في .gitignore
[ ] N8N_ENCRYPTION_KEY محفوظ في مدير كلمات مرور
```

⚠️ **كتبتَ مفتاحًا في مكان خاطئ ولو مرة؟ اعتبره مسرَّبًا وأبطِله فورًا.**

## Webhooks
```
[ ] مصادقة مفعّلة (Header / Basic / HMAC)
[ ] مسار غير قابل للتخمين (UUID)
[ ] تحقق من محتوى الطلب
[ ] حد أقصى لحجم الطلب
[ ] HMAC إن كانت الخدمة تدعمه
```

| الطبقة | القوة |
|---|---|
| مسار عشوائي | ضعيفة وحدها |
| Header Auth | ✅ الحد الأدنى |
| HMAC | ✅✅ الأقوى |
| تحقق المحتوى | ✅ إلزامية |

## قاعدة البيانات
```
[ ] استعلامات معاملية فقط ($1, $2)
[ ] مستخدم مخصص بأقل صلاحية
[ ] SSL مفعّل
[ ] قصر الوصول بعنوان IP إن أمكن
[ ] نسخ احتياطية مُختبَرة
```

🔐 **SQL Injection:**
```
❌ WHERE email = '{{ $json.email }}'
✅ WHERE email = $1
```

## التحقق من المدخلات
```
[ ] قائمة مسموحة (Allowlist) لا ممنوعة
[ ] التحقق من النوع
[ ] حد أقصى للطول
[ ] التحقق من الصيغة (بريد · هاتف)
[ ] رفض ما هو خارج القيم المعروفة
```

## الخصوصية
```
[ ] لا نجمع ما لا نحتاج ⭐
[ ] لا أسرار ولا بيانات شخصية كاملة في السجلات
[ ] سياسة احتفاظ محددة
[ ] آلية حذف عند طلب صاحب البيانات
[ ] تشفير أثناء النقل وفي التخزين
[ ] موافقة العميل على إرسال محتواه لمزوّد AI
```

⭐ **البيانات التي لا تجمعها لا يمكن تسريبها.**

## الوصول
```
[ ] مراجعة من يملك وصولًا لـ n8n
[ ] مصادقة ثنائية مفعّلة
[ ] إنتاج منفصل عن التطوير
[ ] إزالة وصول من غادر الفريق
```

## AI
```
[ ] Session ID مضبوط (منع اختلاط المحادثات) ⭐
[ ] لا بيانات حساسة في الأوامر بلا داع
[ ] حدود صارمة للرد التلقائي
[ ] تصعيد بشري للحالات الحساسة
```
