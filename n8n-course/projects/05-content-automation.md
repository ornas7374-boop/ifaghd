# Project 5 — نظام أتمتة المحتوى

> 🥇 **المستوى:** Advanced · **الوحدات:** M10, M11, M15 · **الزمن:** 6–8 ساعات
> **الهدف:** نظام إنتاج محتوى بـ **تدخل بشري** ومسارات متعددة.

---

## 1. تحليل المتطلبات

### المشكلة
صانع محتوى ينشر على منصات متعددة. الدورة الكاملة (فكرة → بحث → نص → تكييف لكل منصة → جدولة) تستغرق 4 ساعات لكل موضوع.

### المتطلبات

| النوع | المتطلب |
|---|---|
| **وظيفي** | مصادر أفكار: إدخال يدوي · جدول أفكار · اقتراح AI |
| **وظيفي** | بحث وجمع مراجع |
| **وظيفي** | توليد نص أساسي |
| **وظيفي** | تكييف لكل منصة (طول ونبرة مختلفة) |
| **وظيفي** | **مراجعة بشرية إلزامية قبل النشر** |
| **وظيفي** | حفظ كل النسخ في قاعدة بيانات |
| **غير وظيفي** | إضافة منصة جديدة بلا إعادة بناء |

### معيار النجاح
> من فكرة إلى مسودات جاهزة لكل المنصات في أقل من 10 دقائق · صفر نشر بلا مراجعة.

## 3. مخطط قاعدة البيانات

```sql
CREATE TABLE topics (
  id         BIGSERIAL PRIMARY KEY,
  title      TEXT NOT NULL,
  angle      TEXT,
  keywords   TEXT[],
  status     TEXT NOT NULL DEFAULT 'idea',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE content_pieces (
  id          BIGSERIAL PRIMARY KEY,
  topic_id    BIGINT NOT NULL REFERENCES topics(id) ON DELETE CASCADE,
  platform    TEXT NOT NULL,
  body        TEXT NOT NULL,
  status      TEXT NOT NULL DEFAULT 'draft',
  reviewed_by TEXT,
  reviewed_at TIMESTAMPTZ,
  scheduled_at TIMESTAMPTZ,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (topic_id, platform)     -- ⭐ يمنع تكرار نفس المحتوى لنفس المنصة
);

-- ⭐ إضافة منصة = صف جديد، لا تعديل workflow
CREATE TABLE platforms (
  name        TEXT PRIMARY KEY,
  max_length  INTEGER NOT NULL,
  tone        TEXT NOT NULL,
  format_hint TEXT,
  active      BOOLEAN NOT NULL DEFAULT TRUE
);

INSERT INTO platforms VALUES
('twitter',   280,   'مختصر وحاد',        'خيط من 3-5 تغريدات', TRUE),
('linkedin',  3000,  'مهني وتحليلي',      'فقرات قصيرة',        TRUE),
('instagram', 2200,  'ودود وبصري',        'مع وسوم',            TRUE),
('newsletter',10000, 'تفصيلي وشخصي',      'عناوين فرعية',       TRUE);
```

> 💎 **جدول `platforms` هو محور المعمارية.**
> إضافة "تيك توك"؟ **صف واحد.** بلا لمس أي workflow.
> بلا هذا الجدول، ستضيف فرعًا في Switch لكل منصة — وبعد ست منصات يصبح النظام غير قابل للصيانة.

## 4. الأوامر

### توليد المحتوى الأساسي
```
الدور:   كاتب محتوى متخصص في [المجال]
المهمة:  اكتب محتوى أساسيًا شاملًا عن الموضوع المعطى
المدخل:  العنوان · الزاوية · المراجع المجمّعة
القواعد:
  - اعتمد على المراجع المعطاة فقط ولا تخترع إحصاءات
  - اذكر مصدر أي رقم
  - اكتب بأسلوب طبيعي لا آلي
  - لا تستخدم عبارات مبتذلة
المخرج:  نص أساسي منظّم بعناوين فرعية
```

### التكييف لمنصة
```
الدور:   محرر يكيّف المحتوى لمنصات مختلفة
المدخل:  النص الأساسي + إعدادات المنصة (من جدول platforms)
القواعد:
  - لا تتجاوز {{ max_length }} حرفًا
  - استخدم نبرة: {{ tone }}
  - الشكل: {{ format_hint }}
  - حافظ على الأفكار الأساسية ولا تضف معلومات جديدة
```

> 💡 **الأمر نفسه لكل المنصات — المتغير هو الإعدادات.**
> هذا يعني: تحسين الأمر مرة واحدة يحسّن كل المنصات. أما أمر منفصل لكل منصة فيعني صيانة ستة أوامر.

## 5. التدخل البشري

📌 استخدم عملية **`sendAndWait`** (متاحة في Telegram · Gmail · Discord · Google Chat · Send Email).

```
[إنشاء المسودة]
      ▼
[Telegram: sendAndWait]  ← يعرض المسودة مع أزرار: اعتماد / رفض
      ▼
[Switch حسب الرد]
   ├─ اعتماد → status='approved' → جدولة
   └─ رفض    → status='rejected' → أرشفة أو إعادة توليد
```

> ⚠️ **`sendAndWait` يوقف التنفيذ في انتظار الرد.**
> **اضبط مهلة زمنية** — وإلا بقيت التنفيذات معلّقة إلى الأبد وتستهلك الموارد.
> **صمّم سلوك انتهاء المهلة:** أرشفة تلقائية؟ تذكير؟ تصعيد؟ قرر مسبقًا.

## 6. الاختبار

| # | السيناريو | المتوقع |
|---|---|---|
| 1 | موضوع كامل | مسودة لكل منصة نشطة |
| 2 | تعطيل منصة (`active=false`) | تُتخطى تلقائيًا |
| 3 | إضافة منصة جديدة (صف واحد) | تظهر في الدورة التالية بلا تعديل |
| 4 | فشل توليد لمنصة واحدة | الباقي يكتمل · تنبيه للفاشلة |
| 5 | نص يتجاوز الحد | يُقصّ أو يُعاد توليده |
| 6 | نفس الموضوع مرتين | لا تكرار (قيد `UNIQUE`) |
| 7 | رفض المراجعة | لا نشر · حالة `rejected` |
| 8 | انتهاء مهلة المراجعة | السلوك المصمَّم يعمل |

## 7. التحسين وضبط التكلفة

| التحسين | الفائدة |
|---|---|
| توليد النص الأساسي **مرة واحدة** | التكييف أرخص بكثير من التوليد الكامل |
| نموذج أصغر للتكييف | التكييف أبسط من التوليد |
| تخزين المراجع المجمّعة | لا تعيد البحث لمواضيع مترابطة |
| توليد على دفعات ليلية | استغلال أوقات أقل ازدحامًا |

> 💡 **قرار التصميم الأهم للتكلفة:** نص أساسي واحد + تكييفات، بدلًا من توليد كامل مستقل لكل منصة.
> **الوفر:** 4 منصات = استدعاء توليد واحد + 4 تكييفات، بدل 4 استدعاءات توليد كاملة.
