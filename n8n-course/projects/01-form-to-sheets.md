# Project 1 — Form → Google Sheets → Email

> 🥉 **المستوى:** Beginner · **الوحدات:** M1–M3 · **الزمن:** 90–120 دقيقة
> **الهدف:** أول نظام كامل يعمل فعليًا — من مدخل بشري إلى تخزين وإشعار.

---

## 1. تحليل المتطلبات

### المشكلة
شركة تستقبل طلبات عروض أسعار عبر رسائل واتساب ومكالمات. لا سجل موحّد، وتضيع طلبات، ولا أحد يعرف من تابع من.

### الحل المقترح
نموذج ويب يجمع الطلبات في جدول واحد، مع إشعار فوري للفريق.

### المتطلبات

| النوع | المتطلب |
|---|---|
| **وظيفي** | نموذج يجمع: الاسم · الجوال · نوع الخدمة · الميزانية · الملاحظات |
| **وظيفي** | كل طلب يُحفظ صفًا في Google Sheets مع ختم زمني |
| **وظيفي** | إشعار بريدي فوري للفريق بملخص الطلب |
| **غير وظيفي** | لا طلب يضيع · النموذج يعمل على الجوال |
| **خارج النطاق** | الرد التلقائي على العميل · التقييم بالذكاء الاصطناعي (مشاريع لاحقة) |

### معيار النجاح
> 100% من الطلبات المُرسَلة تظهر في الجدول خلال 10 ثوانٍ، ويصل إشعار لكل طلب.

## 2. المعمارية

```
┌──────────────┐
│  Form Trigger│  ← نموذج n8n العام (رابط يُشارَك)
└──────┬───────┘
       │  { name, phone, service, budget, notes }
       ▼
┌──────────────┐
│ تطبيع البيانات│  ← Set: توحيد الهاتف · إضافة ختم زمني · معرّف الطلب
└──────┬───────┘
       │
       ├──────────────────┐
       ▼                  ▼
┌──────────────┐   ┌──────────────┐
│Google Sheets │   │  Gmail       │
│  (append)    │   │  (إشعار)     │
└──────────────┘   └──────────────┘
```

### لماذا هذا التصميم؟

| القرار | السبب |
|---|---|
| **Form Trigger** لا Webhook | لا نحتاج موقعًا ولا مطور واجهات — نموذج جاهز برابط |
| **Set** قبل الفروع | نطبّع مرة واحدة بدل تكرار المنطق في كل فرع |
| **فرعان متوازيان** | الحفظ والإشعار مستقلان — فشل الإشعار لا يمنع الحفظ |
| **Sheets لا قاعدة بيانات** | العميل يريد رؤية البيانات وتحريرها بنفسه |

## 5. التنفيذ خطوة بخطوة

### الخطوة 1 — النموذج
أضف **n8n Form Trigger** وعرّف الحقول:

| الحقل | النوع | مطلوب؟ |
|---|---|---|
| `name` | Text | ✅ |
| `phone` | Text | ✅ |
| `service` | Dropdown (تصميم / تطوير / استشارة) | ✅ |
| `budget` | Number | ⬜ |
| `notes` | Textarea | ⬜ |

> ⭐ **Dropdown بدل نص حر للخدمة.** يمنع تنوّع الكتابة (`تصميم` · `التصميم` · `desgin`) الذي يفسد أي تصنيف أو تقرير لاحق.
> **درس عام:** كل حقل نصي حر هو فوضى مستقبلية. قيّده بخيارات كلما أمكن.

### الخطوة 2 — التطبيع (Set)

| الحقل | القيمة |
|---|---|
| `request_id` | `{{ 'REQ-' + $now.toFormat('yyyyMMdd') + '-' + $execution.id }}` |
| `submitted_at` | `{{ $now.toFormat('yyyy-MM-dd HH:mm') }}` |
| `phone_clean` | `{{ '+966' + $json.phone.replace(/\D/g,'').replace(/^(966\|0)/,'') }}` |
| `budget_num` | `{{ Number($json.budget) \|\| 0 }}` |
| `status` | `جديد` |

> 💡 **لماذا `request_id`؟** ليكون لكل طلب معرّف يُذكر في المراسلات والتشخيص.
> **لماذا `phone_clean`؟** لتوحيد الصيغة ومنع تكرار نفس العميل بصيغ مختلفة.

### الخطوة 3 — Google Sheets
- Operation: **Append**
- أنشئ الجدول بالأعمدة: `request_id | submitted_at | name | phone_clean | service | budget_num | notes | status`

### الخطوة 4 — Gmail
```
الموضوع: 🔔 طلب جديد: {{ $json.service }} — {{ $json.name }}

المحتوى:
رقم الطلب: {{ $json.request_id }}
الاسم:     {{ $json.name }}
الجوال:    {{ $json.phone_clean }}
الخدمة:    {{ $json.service }}
الميزانية: {{ $json.budget_num }}
ملاحظات:   {{ $json.notes || 'لا يوجد' }}
الوقت:     {{ $json.submitted_at }}
```

> ⚠️ لاحظ `|| 'لا يوجد'` — الحقول الاختيارية قد تصل فارغة.

### الخطوة 5 — التفعيل
فعّل **Active** واستخدم رابط النموذج **الإنتاجي**.

## 6. الاختبار

| # | السيناريو | المتوقع |
|---|---|---|
| 1 | إرسال كامل البيانات | صف في الجدول + إشعار |
| 2 | ترك الحقول الاختيارية فارغة | يعمل · "لا يوجد" في الملاحظات |
| 3 | جوال بصيغة `0501234567` | يُحفظ `+966501234567` |
| 4 | جوال بصيغة `+966 50 123 4567` | نفس النتيجة |
| 5 | إرسالان متتاليان | صفان بمعرّفين مختلفين |
| 6 | فتح النموذج على الجوال | يعمل بشكل سليم |

> ⚠️ **السيناريوهان 3 و 4 هما جوهر الاختبار.** إن أعطيا نتائج مختلفة، فالتطبيع فاشل.

---

## 7. معالجة الأخطاء

| السيناريو | المعالجة |
|---|---|
| فشل Gmail | فعّل `Continue On Fail` على عقدة Gmail — **الحفظ أهم من الإشعار** |
| فشل Sheets | لا تُكمل — هذا فشل حرج، يجب أن يتوقف ويُبلَّغ |
| حقل ناقص | Form Trigger يفرض الحقول المطلوبة |

> 🧠 **قرار معماري مهم:** ليست كل الأخطاء متساوية.
> فقدان الإشعار مزعج، لكن **فقدان الطلب كارثة**. رتّب معالجتك حسب الأثر لا حسب الترتيب في المسار.
