# Project 3 — Gmail → AI → تصنيف → مسودة رد

> 🥈 **المستوى:** Intermediate · **الوحدات:** M10, M11 · **الزمن:** 3–4 ساعات
> **الهدف:** أول نظام AI إنتاجي — بمخرج منظَّم وبوابة ثقة وتدخل بشري.

---

## 1. تحليل المتطلبات

### المشكلة
صاحب عمل يستقبل 40–60 بريدًا يوميًا مختلطة: استفسارات أسعار · شكاوى · عروض إعلانية · طلبات دعم. يقضي ساعة يوميًا في الفرز قبل الرد.

### الحل
تصنيف تلقائي + **مسودة** رد جاهزة للمراجعة — **لا إرسال تلقائي**.

> ⚠️ **قرار تصميم جوهري: لا نرسل تلقائيًا.**
> رسالة خاطئة باسم العميل تضر سمعته ضررًا لا يُصلحه أي وفر في الوقت.
> **المسودة تعطي 80% من الفائدة بـ 5% من المخاطرة.** هذه معادلة تستحق التذكر في كل مشروع AI.

### المتطلبات

| النوع | المتطلب |
|---|---|
| **وظيفي** | فحص البريد الجديد دوريًا |
| **وظيفي** | تصنيف إلى: `PRICE_INQUIRY` · `COMPLAINT` · `SUPPORT` · `SPAM` · `OTHER` |
| **وظيفي** | إضافة تسمية (Label) في Gmail حسب التصنيف |
| **وظيفي** | إنشاء **مسودة** رد للفئات التي تستحق ردًا |
| **وظيفي** | تنبيه فوري عند شكوى |
| **خارج النطاق** | الإرسال التلقائي |

### معيار النجاح
> دقة تصنيف > 90% على 50 رسالة اختبار · صفر رسائل مُرسَلة تلقائيًا · تنبيه فوري لكل شكوى.

## 2. المعمارية

```
┌──────────────┐
│ Gmail Trigger│  ← فحص دوري للبريد الجديد
└──────┬───────┘
       ▼
┌──────────────┐
│ Set: تحضير   │  ← استخراج المرسل والموضوع والنص · اقتطاع الطول
└──────┬───────┘
       ▼
┌──────────────────────┐
│  AI: تصنيف واستخراج  │  Temperature = 0
│ + Structured Output  │  → {category, sentiment, urgency,
└──────┬───────────────┘      confidence, summary, needs_human}
       ▼
┌──────────────────────┐
│ IF: confidence > 0.8 │  ← بوابة الثقة
└───┬──────────────┬───┘
 صح │              │ خطأ
    ▼              ▼
┌─────────┐  ┌─────────────────┐
│ Switch  │  │ تسمية: مراجعة   │
│ حسب     │  │ يدوية           │
│ الفئة   │  └─────────────────┘
└─┬─┬─┬─┬┘
  │ │ │ └── SPAM ──────► أرشفة
  │ │ └──── SUPPORT ───► تسمية + مسودة
  │ └────── COMPLAINT ─► تسمية + 🚨 تنبيه فوري + مسودة
  └──────── PRICE ─────► تسمية + مسودة عرض
       │
       └── Fallback ───► تسمية: غير مصنّف   ← ⭐ إلزامي
```

## 3. القرارات التقنية

| القرار | البديل المرفوض | السبب |
|---|---|---|
| **مسودة** لا إرسال | إرسال تلقائي | خطأ واحد يضر السمعة |
| `Temperature = 0` | الافتراضي | ثبات التصنيف وقابلية الاختبار |
| **Structured Output** | نص حر | لا يمكن بناء Switch على نص حر |
| **بوابة ثقة** | ثقة عمياء | الحالات الغامضة تحتاج بشرًا |
| **Fallback في Switch** | بدونه | فئة غير متوقعة تختفي بصمت |
| **اقتطاع نص الرسالة** | إرسال كامل | تقليل التكلفة وتجنّب حدود السياق |

## 4. الأمر (Prompt)

```
الدور:
أنت مساعد تصنيف بريد لشركة خدمات تقنية.

المهمة:
صنّف الرسالة إلى فئة واحدة فقط واستخرج البيانات المطلوبة.

الفئات:
- PRICE_INQUIRY : سؤال عن الأسعار أو طلب عرض
- COMPLAINT     : شكوى أو استياء من خدمة
- SUPPORT       : طلب مساعدة تقنية لعميل حالي
- SPAM          : إعلان أو رسالة غير مرغوبة
- OTHER         : لا ينطبق عليه ما سبق

القواعد:
- اختر فئة واحدة فقط
- إن كان النص غامضًا استخدم OTHER واخفض confidence
- لا تخترع فئات جديدة
- إن ظهر غضب أو تهديد بإجراء، اضبط needs_human = true
- confidence رقم بين 0 و 1 يعبّر عن يقينك الفعلي

أمثلة:
"كم سعر الباقة الشهرية؟"           → PRICE_INQUIRY, confidence 0.95
"الخدمة متوقفة من يومين!"           → COMPLAINT, urgency high, needs_human true
"نقدم لكم خدمات تسويق بأسعار مميزة" → SPAM, confidence 0.9
```

### مخطط المخرج (Structured Output Parser)
```json
{
  "category":    "PRICE_INQUIRY | COMPLAINT | SUPPORT | SPAM | OTHER",
  "sentiment":   "positive | neutral | negative",
  "urgency":     "low | medium | high",
  "confidence":  0.0,
  "summary":     "ملخص بجملة واحدة",
  "needs_human": false
}
```

> ⚠️ **الوصول للمخرج:** `{{ $json.output.category }}` — مغلَّف في `output`.
> هذا أشهر سبب لـ `undefined` في مشاريع AI.

## 5. الاختبار

| # | السيناريو | المتوقع |
|---|---|---|
| 1 | "كم سعر الباقة؟" | `PRICE_INQUIRY` · ثقة عالية |
| 2 | "الخدمة سيئة وسأقدم شكوى!" | `COMPLAINT` · `needs_human: true` · تنبيه فوري |
| 3 | إعلان تسويقي | `SPAM` · أرشفة |
| 4 | رسالة غامضة من كلمتين | `OTHER` أو ثقة منخفضة → مراجعة |
| 5 | رسالة بلا نص (موضوع فقط) | لا انهيار |
| 6 | رسالة طويلة جدًا (10 آلاف كلمة) | تُقتطع ولا تفشل |
| 7 | رسالة بالإنجليزية | تُصنَّف بشكل صحيح |
| 8 | 20 رسالة دفعة واحدة | كلها تُعالَج بلا تجاوز حد المعدل |

> 🧪 **اختبار الدقة الإلزامي:** جهّز **50 رسالة حقيقية** وصنّفها يدويًا، ثم قارن بمخرج النظام.
> **إن كانت الدقة < 90%، حسّن الأمر — لا تسلّم.**
> هذا الاختبار هو الفرق بين "بنيتُ نظام AI" و "بنيتُ نظام AI يعمل".

## 6. معالجة الأخطاء

| الفشل | المعالجة |
|---|---|
| فشل استدعاء AI | Retry ×2 → تسمية "فشل التصنيف" → تنبيه |
| فشل تحليل المخرج | تسمية "مراجعة يدوية" — **لا تخمّن** |
| ثقة منخفضة | بوابة الثقة → مراجعة يدوية |
| فئة غير متوقعة | Fallback في Switch |
| تجاوز حد Gmail | تقليل حجم الدفعة |

## 7. الأمان والخصوصية

```
[ ] محتوى البريد يُرسل لمزوّد AI — هل هذا مقبول؟ 🔐
[ ] لا تُسجَّل محتويات الرسائل كاملة في السجلات
[ ] صلاحيات Gmail: قراءة + تسميات + مسودات فقط (لا إرسال)
[ ] اقتطاع النص يقلل البيانات المُرسَلة خارجيًا
```

> 🔐 **نقطة حرجة عند التسليم لعميل:**
> **أبلغه صراحةً أن محتوى بريده سيُرسل لمزوّد خارجي، واحصل على موافقته.**
> هذه ليست تفصيلة — بل شرط أخلاقي وقانوني، وقد تكون شرطًا تعاقديًا حسب مجال العميل.
> **الميزة المهنية:** طرح هذا السؤال بنفسك يبني ثقة أكثر مما يثير قلقًا — يُظهر أنك تفكر في مصلحته.

> 🔐 **صلاحيات Gmail:** لا تمنح صلاحية الإرسال ما دمنا ننشئ مسودات فقط.
> هذا يجعل الإرسال التلقائي **مستحيلًا تقنيًا** لا مجرد ممنوع منطقيًا — وهذا أقوى بكثير.

## 8. التحسين

| التحسين | الفائدة |
|---|---|
| **Text Classifier** بدل AI Agent | أرخص وأسرع وأدق لمهمة التصنيف |
| تصفية SPAM بقواعد قبل AI | لا تدفع مقابل تصنيف الإعلانات الواضحة |
| تخزين نتائج التصنيف | تحليل الأنماط وتحسين الأمر |
| قوالب ردود جاهزة | مسودات أسرع وأقل تكلفة |

> 💡 **التحسين الأول هو الأهم:** هذه المهمة **تصنيف لفئات معروفة** — لا تحتاج وكيلًا.
> **Text Classifier** (v1.1) يعطي مخرجًا منفصلًا لكل فئة مباشرة، ويغنيك عن Switch كاملة.
